⏺ Here is the full explanation, building up from first principles.

  ---
  The kernel is a function of θ, not a static matrix

  The neighbour kernel K(θ) is not a single weight matrix — it is a
  matrix-valued function of the neighbour angle θ. For each angle at which a
  neighbour can sit, the kernel produces a different linear map from input
  features to output features.

  An unconstrained kernel of this kind would have infinite degrees of freedom
  (arbitrary Fourier series). The equivariance constraint is what collapses it
  to a finite, small number of free parameters.

  ---
  The equivariance constraint as a Fourier filter

  The constraint is:

  K(θ - g) = ρ_out(-g) · K(θ) · ρ_in(g)    for all θ, g

  The key trick: set g = θ. Then:

  K(0) = ρ_out(-θ) · K(θ) · ρ_in(θ)
    ↓
  K(θ) = ρ_out(θ) · K(0) · ρ_in(-θ)   [rearranging]
       = R(n_out · θ) · A · R(-n_in · θ)

  where A = K(0) is any matrix of the right shape, and R(α) is a 2D rotation by
  α. This means the entire kernel is determined by its value at θ = 0. The
  equivariance constraint is not a restriction on A — it just tells you how the
  kernel varies with θ once A is chosen.

  The number of free weights = number of independent entries in A.

  ---
  Why each case has the count it does

  ρ₀ → ρ₀ : 1 basis kernel

  K(θ) maps a scalar to a scalar, so it's a 1×1 function. ρ₀ = [1] always, so:

  K(θ) = R(0·θ) · A · R(-0·θ) = 1 · A · 1 = A   (a constant)

  The constraint forces K to be completely independent of θ — a scalar-to-scalar
   kernel cannot "see" the direction of the neighbour at all, because there's no
   rotational structure on either side to encode direction. A is a 1×1 scalar →
  1 free weight.

  return torch.ones(E, 1, 1, 1)   # shape: (E, 1, 1, 1 basis)

  ρ₀ → ρₙ (n > 0) : 2 basis kernels

  K(θ) maps a scalar (dim 1) to a vector (dim 2), so A is a 2×1 matrix — it has
  2 free entries:

  K(θ) = R(n·θ) · [a, b]ᵀ = [a·cos(nθ) - b·sin(nθ),
                                a·sin(nθ) + b·cos(nθ)]ᵀ

  The two basis kernels correspond to a=1,b=0 and a=0,b=1:

  B₀(θ) = [cos(nθ), sin(nθ)]ᵀ
  B₁(θ) = [-sin(nθ), cos(nθ)]ᵀ   (which is [sin(nθ), -cos(nθ)]ᵀ rotated — same
  span)

  Physically: a scalar input can only produce an output vector that oscillates
  at frequency n in angle. The direction it points (which of the two quadrature
  phases) is the free choice.

  k0 = [cos(n_out * θ),  sin(n_out * θ)]ᵀ
  k1 = [sin(n_out * θ), -cos(n_out * θ)]ᵀ

  ρₙ → ρ₀ (n > 0) : 2 basis kernels (symmetric to above)

  Same argument, transposed. A is a 1×2 matrix, 2 free entries. The vector input
   can only be "read out" into a scalar through a row that oscillates at
  frequency n.

  ρₙ → ρₘ (both > 0) : 4 basis kernels

  K(θ) maps a 2D vector to a 2D vector, so A is a 2×2 matrix — 4 free entries:

  K(θ) = R(m·θ) · A · R(-n·θ)

  Expanding via product-to-sum trig identities, this produces Fourier modes at
  exactly two frequencies: p = m+n and q = |m-n|. Each frequency contributes two
   basis kernels (a cos and a sin phase), giving 4 total:

  ┌───────┬───────────────────┬────────────────────────────────────────────┐
  │ Basis │ Angular frequency │                    Form                    │
  ├───────┼───────────────────┼────────────────────────────────────────────┤
  │ k0    │ q = |m−n|         │ R(q·θ) — the "difference" rotation         │
  ├───────┼───────────────────┼────────────────────────────────────────────┤
  │ k1    │ q = |m−n|         │ R(q·θ + π/2) — 90° phase shift             │
  ├───────┼───────────────────┼────────────────────────────────────────────┤
  │ k2    │ p = m+n           │ symmetric outer product at frequency p     │
  ├───────┼───────────────────┼────────────────────────────────────────────┤
  │ k3    │ p = m+n           │ antisymmetric outer product at frequency p │
  └───────┴───────────────────┴────────────────────────────────────────────┘

  The difference frequency q captures how much the output vector "tracks" the
  rotation of the input vector. The sum frequency p captures higher-order
  oscillations that can only appear when both input and output have rotational
  character.

  For ρ₁→ρ₁ specifically: p=2, q=0. The q=0 basis kernels are angle-independent
  (they just mix channels), and the p=2 basis kernels modulate at twice the
  angle — this is the richer structure compared to ρ₀→ρ₁.

  ---
  How the weights multiply the basis kernels

  The full kernel for a layer with multiplicities (say 8ρ₁ input, 16ρ₁ output)
  is:

  K_{i,j}(θ) = Σ_b  w[i, j, b] · B_b(θ)
                ↑           ↑
            scalar          fixed angular function
            (learned)       (frozen)

  For each pair of channels (i, j) — i.e., each (i of the 16 output ρ₁ channels,
   j of the 8 input ρ₁ channels) — there are 4 free weights, one per basis
  kernel. The weights say "how much does the direction-tracking mode k0
  contribute to this channel pair, how much does the high-frequency mode k2
  contribute, etc."

  Total for 8ρ₁ → 16ρ₁: 4 bases × 8 × 16 = 512 weights
  Compare to 8ρ₀ → 16ρ₀: 1 basis × 8 × 16 = 128 weights
  And 8ρ₀ → 16ρ₁: 2 bases × 8 × 16 = 256 weights

  The table in count_parameters_neigh is doing exactly:

  total += _n_basis_neigh(n_in, n_out) * m_in * m_out
  #         ↑ number of angular modes     ↑ channel pairs

  ---
  The bottom line

  The equivariance constraint is a Fourier filter on the space of all periodic 
  matrix-valued functions. It allows only the angular frequencies that are
  consistent with how the input and output feature types rotate under gauge
  changes. The number of basis kernels is simply the number of independent
  Fourier modes that survive this filter — 1 for scalars (no angular structure),
   2 when only one side has rotational structure, and 4 when both sides do (two
  quadrature phases × two allowed frequencies).

⏺ Good catch on the confusion — let me clarify. They're not the same thing
  counted twice. They're two separate weight matrices in the GEM update rule:

  f'_p = K_self · f_p  +  Σ_{q∈N(p)} K_neigh(θ_pq) · ρ_in(g_{q→p}) · f_q
           ↑                              ↑
     self-connection               neighbour aggregation
     (no θ, no transport)          (depends on angle θ)

  - K_neigh ρ₀→ρ₀ (192 weights): applied to each neighbour's features, scaled by
   their angle θ. Even for ρ₀→ρ₀ where the kernel is constant (doesn't vary with
   θ), it's still a separate linear map that aggregates from the neighbourhood.
  - K_self ρ₀→ρ₀ (192 weights): applied only to the vertex's own features, no
  angle involved. This is the skip/residual-style self-loop, analogous to the
  Wh_i term in standard GCN.

  They happen to have the same shape and the same number of basis kernels (1 for
   ρ₀→ρ₀), but they're independently learned and serve different roles — one
  reads from the vertex itself, the other reads from its neighbourhood.

  So the total 768 is correct:
  K_neigh ρ₀→ρ₀:   192   (neighbours, constant in θ)
  K_neigh ρ₀→ρ₁:   384   (neighbours, varies with θ)
  K_self  ρ₀→ρ₀:   192   (self, no θ)
  K_self  ρ₀→ρ₁:     0   (self, forbidden by equivariance)
  ─────────────────────
  Total:            768
